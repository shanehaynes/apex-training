### `Analytics/AnalyticsModel.swift`
- [ ] **P1** · *Duplication G5 / Inconsistency G11 (error handling)* · `Analytics/AnalyticsModel.swift:370` — `isNetwork(_:)` and `readable(_:)` (370–381) are a second error-to-text translator next to `Failure.message` (`Profile/YouServices.swift:96`, used by Blocks, Library, Coros and Connector) and a third `ScheduleModel.isNetwork` (`Schedule/ScheduleModel.swift:823`, used by `BuilderModel`). The same offline sentence then gets rebuilt inline as a `isNetwork(error) ? "No connection — couldn't X." : "Couldn't X — try again"` ternary at 269, 309 and 329, and again as the save copy in `TileBuilderModel.swift:247` and `BuilderModel.swift:249`. The result is three different offline messages ("No connection. Showing what was last synced.", "You're offline — try again when connected.", "No connection — couldn't …"). **Fix:** move one `Failure` (or `APIError` extension) into ApexCore/ApexUI with `isNetwork` plus `message(_ error:, action: "save the layout")` that builds both the offline and generic copy. Then delete `AnalyticsModel.isNetwork/readable` and `ScheduleModel.isNetwork`, and route every ternary through it.
- [ ] **P2** · *Duplication G5 / Functions — do one thing* · `Analytics/AnalyticsModel.swift:316` — `commitEdit` (255), `duplicate` (280) and `delete` (316) each copy the same optimistic-write recipe: snapshot `tiles` (and the result), mutate, `try await client.data`, restore and toast on failure, then `persistTiles()`. Each caller then shrinks to its mutation plus its copy, and `delete` passes `tolerate: { $0.isServer(404) }`.
- [ ] **P2** · *Feature envy G14* · `Analytics/AnalyticsModel.swift:286` — `duplicate` reaches into the tile's opaque `spec` JSON and rewrites its `"title"` key by hand (`if case .object(var object) = spec { object["title"] = … }`).
