### `Cache/WriteQueue.swift`
- [ ] **P1** · *Functions — small, do one thing (G30, G34)* · `Cache/WriteQueue.swift:167` — `drain(_:)` runs about 100 lines (167–270) and mixes five concerns at different levels of abstraction: sending the op and mapping errors, cancel-mid-flight cleanup, decoding a 200 `DraftVerdict` refusal, the timestamp-window resend, and the three-way `RetryPolicy` verdict with its completion/quick-complete side effect. Every queue rule lands in this one loop body, so it is the hardest function in the module to change safely. **Fix:** keep `drain` as the loop. Extract `send(_ op:) async -> Result<Data, APIError>`, `handleSuccess(_ op:, data:, in:) async -> DrainStep`, and `handleFailure(_ op:, error:, resumesBefore:, in:) async -> DrainStep`, where `DrainStep` is `.next` or `.stop`.
- [ ] **P1** · *Error handling — swallowed errors* · `Cache/WriteQueue.swift:230` — Every store write in the queue discards its error with `try?` (187, 203, 208, 222, 230, 258, 295, 380, 405, 413, 435, 455, 457, 590). A failed `store.update(next)` after a `.retry` verdict keeps the op's old `attempts`, so the `maxAttempts` ceiling never arrives and the op retries forever. A failed `store.delete` after a 2xx re-sends a write that already landed. Nothing logs or surfaces either case. **Fix:** let store calls throw inside `drain`/`repend`/`letGo`, and catch once per public entry point. That handler pauses the queue and emits a `QueueEvent.storeFailed(SessionKey, String)`, or at minimum logs, so the store failing is a visible state rather than silent drift. — drain's six writes (187, 203, 208, 222, 230, 258) fixed in #PRNUM: a failed write stops the drain, emits `storeFailed`, backs off. Still open: the user-action paths (`repend`, `retryFailed`, `discardFailed`, `letGo`, `discard`) and `retireQuickComplete`'s delete.
- [ ] **P2** · *Duplication (G5)* · `Cache/WriteQueue.swift:199` — The same four-line "record a failed attempt" mutation (`var next = op; next.attempts += 1; next.lastError = …; [next.state = .failed]`) is written four times: 199–202, 219–222, 227–230 and 249–252. **Fix:** add `TrackerOp.recordingAttempt(error: String, failing: Bool = false) -> TrackerOp` and call it at each site.
- [ ] **P2** · *Duplication (G5)* · `Cache/WriteQueue.swift:374` — `repend(gaveUpIn:)` (375–381) and `retryFailed(_:)` (400–406) contain the same loop that resets `state/attempts/lastError/gaveUp`. They differ only in the filter (`gaveUp` or any failed op). **Fix:** add `mutating func TrackerOp.resetForRetry()` and one private `repend(in:where:)` that both call.
- [ ] **P2** · *Names / output encoding (N1, G16)* · `Cache/WriteQueue.swift:545` — `pendingStart(for:) -> String??` uses a double optional to mean three things: no start queued, a start queued with a nil stamp, or a start with a stamp. Callers have to write `if case .some(let stamp) = …, let stamp` (TrackerModel.swift:242) to tell them apart. **Fix:** return a named enum, e.g. `enum QueuedStart { case none, unstamped, stamped(String) }`, or return the `TrackerOp?` itself.
- [ ] **P2** · *Duplication (G5) / SRP* · `Cache/WriteQueue.swift:563` — The subscriber fan-out (`subscribers` dict plus `subscribe` / `unsubscribe` / `emit`, 563–579) is copied verbatim in `Coach/ChatSession.swift:126–143`. **Fix:** extract a generic `struct EventBroadcaster<Event: Sendable>` with `subscribe(onTerminate:)` and `emit(_:)`, and hold one per actor.
