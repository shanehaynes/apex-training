# Can the Apex coach run on a user's Claude subscription? (O06 research, 2026-09-24)

Read-only lane report, committed verbatim. Feeds decision D-O06.

## 1. Conclusion
- **Supported today: no.** Anthropic's current policy: "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow." Developers, "including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider." (https://code.claude.com/docs/en/legal-and-compliance, "Authentication and credential use"). The Agent SDK docs repeat it: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK." (https://code.claude.com/docs/en/agent-sdk/overview; https://code.claude.com/docs/en/agent-sdk/quickstart). The Consumer Terms forbid sharing account credentials or API keys and forbid "automated or non-human" access except via an API key or where explicitly permitted (https://www.anthropic.com/legal/consumer-terms, effective 2025-10-08, §2 and §3).
- **Technically works but unsupported / against terms:** a subscriber runs `claude setup-token`, pastes the one-year `sk-ant-oat01-…` token into Apex, and the server drives `@anthropic-ai/claude-agent-sdk` with `CLAUDE_CODE_OAUTH_TOKEN` (the mechanism the eval gate uses, D-047). It would run, but Apex would then be storing and intermediating a Claude.ai session token, which is the exact conduct named above; Anthropic "reserves the right to take measures to enforce these restrictions and may do so without prior notice" (legal-and-compliance). It has done so: server-side rejection of subscription tokens outside Claude Code since January 2026 ("This credential is only authorized for use with Claude Code and cannot be used for other API requests", https://docs.moltis.org/anthropic-oauth.html; https://github.com/JetBrains/thinkrail/issues/437), account bans for tools spoofing the harness, and a February 2026 docs clarification with an Anthropic engineer stating "Third-party harnesses using Claude subscriptions create problems for users and are prohibited by our Terms of Service" (https://www.theregister.com/2026/02/20/anthropic_clarifies_ban_third_party_claude_access/).
- **Not possible:** using a subscription token with the plain Messages API / `@anthropic-ai/sdk` that the coach uses today. Subscription OAuth is accepted only through the Claude Code harness; the setup-token "can only make model requests" and only from Claude Code / the Agent SDK (https://code.claude.com/docs/en/authentication, "Generate a long-lived token"). `ant auth login` is not a way around this either: it is a Console OAuth flow, workspace-scoped, "intended for local development and scripting on your own machine", billed as API usage, and servers are told to use Workload Identity Federation (https://platform.claude.com/docs/en/cli-sdks-libraries/cli/authentication).

## 2. What the Agent SDK + setup-token path actually is
- `claude setup-token` runs the normal browser login and prints a one-year OAuth token for `CLAUDE_CODE_OAUTH_TOKEN`; it "requires a Pro, Max, Team, or Enterprise plan", is meant "for CI pipelines and scripts where browser login isn't available", and is ranked below API keys in credential precedence (https://code.claude.com/docs/en/authentication). The Agent SDK spawns the bundled `claude` binary as a subprocess and the hosting guide's only documented server credential is `ANTHROPIC_API_KEY` from a secret manager (https://code.claude.com/docs/en/agent-sdk/hosting, "Auth and secrets"). Use of the SDK itself is under the Commercial Terms (agent-sdk/overview, "License and terms").
- Who gets billed is in flux. On 2026-04-03 Anthropic announced that from 04-04 "Claude subscriptions will no longer cover usage on third-party tools like OpenClaw"; such tools run on "extra usage bundles" or an API key (https://www.threads.com/@boris_cherny/post/DWsAWeND5nm; https://techcrunch.com/2026/04/04/anthropic-says-claude-code-subscribers-will-need-to-pay-extra-for-openclaw-support/). On 2026-05-13 it announced monthly "Agent SDK credits" from 06-15 ($20 Pro / $100 Max 5x / $200 Max 20x) covering "third-party apps that authenticate with your Claude subscription through the Agent SDK" (https://venturebeat.com/technology/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch). The help article now carries: "Update June 15: We're pausing the changes to Claude Agent SDK usage described below … For now, nothing has changed: Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits" (https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan, read 2026-09-24). Either way the subscriber's own account pays and the subscriber's own account is what enforcement hits (inference from the token being theirs).
- Why it is not usable per end-user on a server, even under the credit programme (inference, reconciling the two doc sets): the third-party apps Anthropic names (OpenClaw, Zed, Conductor, T3 Code) run the Claude Code binary / Agent SDK on the user's own machine, where the user signs in through Claude Code's own flow and the token stays in Claude Code's credential store. Apex on Vercel would have to receive and store the token in Supabase and call on the user's behalf — the "collect, store, or intermediate" and "route requests through … credentials on behalf of their users" clauses. The "unless previously approved" carve-out has no published application path other than contact sales (legal-and-compliance, last paragraph). D-047's CI use is defensible only because it is Shane's own token on Shane's own machine (inference; the same page's carve-out for "the customer's own authorized users").

## 3. What /help/get-api-key should tell a subscriber
"A Claude Pro or Max plan does not come with an API key, and Anthropic does not let other apps, like Apex, sign in with your Claude account or spend your plan for you. The coach needs its own key from console.anthropic.com. That key is paid separately, by how much you use, and you can add as little as $5 to start. If Anthropic opens a way to use a subscription with apps like this one, we will add it here."

## 4. Recommendation for D-O06
Research only; do not build. Any subscription path today means asking users to hand Apex a `sk-ant-oat01` token and running the coach through the Agent SDK instead of `@anthropic-ai/sdk`, which is (a) expressly prohibited for third-party developers, (b) enforced server-side and by account action, and (c) billed on a model that changed twice in five months and is currently "paused". Close D-O06 with the help-page wording above, and note two re-open triggers: Anthropic publishes a developer-facing approval/"Sign in with Claude" programme for third-party apps, or the Agent SDK credit programme un-pauses with an explicit path for hosted apps. If Shane wants certainty, the one sanctioned step is the sales contact on the legal page; a personal-training app asking for "previously approved" status is unlikely to be worth the wait (inference).

## 5. Not verified
- No API call was made; that a `sk-ant-oat01` token is rejected by the Messages API today is taken from third-party reports (moltis FAQ, thinkrail issue), not tested.
- The support article's "paused" notice was read via a summarising fetch on 2026-09-24; its wording after that date, and whether the April 2026 extra-usage behaviour still applies in practice, were not checked further.
- The Commercial Terms were not read in full; only the Consumer Terms clauses quoted above were confirmed.
- No contact was made with Anthropic sales, and no public criteria for "previously approved" developers were found.
- Token revocation: the docs give a one-year life but no per-token revoke command (only a feature request, https://github.com/anthropics/claude-code/issues/48373); not verified beyond that.
